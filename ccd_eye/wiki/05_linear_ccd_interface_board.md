## 1. 子系统概述与架构定位

### 1.1 为什么需要独立的接口协处理器？
在 `head` 单元中，主控芯片 **ESP32-WROOM-32** 已经承担了繁重的任务：
- 2 路独立硬件 I2C 颜色传感器（TCS34725）高频读取与状态机滤波；
- 输送步进电机加减速实时脉冲规划（AccelStepper / 硬件定时器）；
- 与下游 `body_1` 的全双工背压握手串口通信。

如果直接由 ESP32 驱动线阵 CCD（如 Toshiba TCD1304，拥有 3648 个感光像元）：
1. **时钟抖动致命伤**：CCD 芯片要求纳秒级确定性的主频（0.5~2MHz）、曝光门脉冲（$\text{SH}$）和转移门脉冲（$\text{ICG}$）。FreeRTOS 的任务调度、Wi-Fi/蓝牙中断乃至底层中断延迟，都会导致软件翻转 GPIO 产生严重时钟抖动，引发基线漂移与暗电流不均；
2. **ADC 采样瓶颈**：ESP32 内部 ADC 非线性度较差、采样率低且容易受 Wi-Fi 射频串扰，无法胜任兆赫兹级连续视频流采集。

### 1.2 黑盒系统模型：传感器与主控之间的智能桥梁
因此，本设计构建了一个专用的**线阵 CCD 智能前置接口小系统（Front-End Interface Coprocessor）**：
- **左边（传感器侧）**：专职对接线阵 CCD 物理引脚，硬件定时器级联驱动严苛时钟，高速精密运放调理信号，片上 ADC + DMA 连续抓取一行像素；
- **核心（计算引擎）**：单片机片内直接运行动态阈值判定与亚像素边缘拟合，直接换算出毫米直径；
- **右边（通信侧）**：通过标准工业 **UART 串口**（配合硬件 TRIG/READY 触发信号），以极简的 ASCII/JSON 报文直接向 `head` (ESP32) 交付测量结果。

### 2.2 专题论证：若协处理器也选用 ESP32 的利弊深度分析

在当前 thin_wall 项目中，`head` 主控单元与下游 `body` 节点均基于 ESP32 构建。如果将本线阵 CCD 接口小系统也选用 **ESP32**（如 ESP32-WROOM-32 或 ESP32-S3），在工程上具备极大的吸引力，但也伴随着不可忽视的物理硬伤。

```
       ┌─────────────────────────────────────────────────────────────┐
       │              ESP32 担任线阵 CCD 协处理器的利弊权衡            │
       └─────────────────────────────────────────────────────────────┘

       【 好处 (Advantages) 】                     【 坏处 (Disadvantages) 】
       ✔ 全系统技术栈绝对统一 (ESP-IDF/PlatformIO)     ✘ 片上 SAR ADC 非线性严重 (头尾死区)
       ✔ 研发备件与 BOM 供应链完全复用 (¥13)        ✘ 片上 ADC 有效位数低 (ENOB 仅 9~10bit)
       ✔ 双核 240MHz 充沛算力 (Core0通信/Core1采集)  ✘ 缺乏通用定时器硬件级联总线 (ITR)
       ✔ RMT/MCPWM 硬件模块可生成无抖动方波         ✘ 开启 Wi-Fi 射频会对模拟信号造成严重毛刺
       ✔ 可拓展 Web/手机端无线波形实时调校
```

#### 1) 核心优势 (好处)
1. **全系统技术栈绝对统一（零心智切换成本）**：
   - 无需为了一个小模组而引入 ARM GCC / Keil / STM32CubeIDE 等多套开发工具链；
   - 固件架构、日志系统、通信协议库（如 ArduinoJson）、构建环境（PlatformIO）与主系统完全一致，极大降低团队协作与长线维护成本；
2. **供应链与备件库复用**：
   - ESP32-WROOM 模组量产单价仅约 ¥12~14，与 STM32 核心板相当，甚至现货供应能力更稳定；
3. **双核并发架构（核分离机制 Core Pinning）**：
   - ESP32 天然具备双核 240MHz 运算能力：
     - **Core 1（专职采集核）**：配置高优先级任务专跑底层 CCD 脉冲生成与 DMA 数据接收；
     - **Core 0（算法通信核）**：专跑暗电流扣除、双边阈值判定、亚像素拟合计算与串口打包发送；
   - 两核之间通过队列（FreeRTOS Queue）无锁通信，彻底避免多任务抢占引起的系统延迟；
4. **无线现场调试与波形可视化彩蛋（极大降低调试门槛）**：
   - 传统单片机在现场调试光路时必须外接示波器查看 3648 点的视频波形；
   - ESP32 自带 Wi-Fi/WebServer。在产线装配标定阶段，可临时开启热点，工程师直接在手机或平板浏览器上拖动查看芦笋通过时的**实时像素阴影曲线**，现场调节背光亮度和物距极为直观。

#### 2) 致命短板与工程缺陷 (坏处)
1. **片上内置 ADC 性能严重不合格（最大的物理阿喀琉斯之踵）**：
   - **非线性极差（DNL / INL 严重失真）**：ESP32 的内部 SAR ADC 在低电压端（$<0.15\text{ V}$）存在明显的测量盲区，在接近参考电压端（$>2.8\text{ V}$）存在严重的非线性饱和压缩。这对于需要依靠灰度平滑过渡进行亚像素插值的线阵 CCD 而言是致命缺陷；
   - **有效位数偏低（ENOB 仅约 9~10 bit）**：内部参考源热噪声较大，若直接使用，会导致提取出的边缘像素产生 $\pm 2 \sim 3$ 个像元的随机跳变；
   - **射频噪声干扰**：若启用了 Wi-Fi 功能，ADC2 将被硬件射频强制独占而完全失效；同时射频发射时的大电流毛刺会直接耦合至 ADC1 模拟采样线上。**因此若用作精密采集，必须永久物理关闭 Wi-Fi/BT 射频电路**；
2. **缺少工业级定时器硬件互连交叉触发（Cross-Triggering）机制**：
   - STM32 的高级定时器支持内部触发输入（ITR），可以实现“TIM1 输出 2MHz 主频 $\rightarrow$ 硬件零延时触发 ADC 规则转换 $\rightarrow$ 硬件触发 DMA 搬运”，全程无需任何 CPU 代码干预；
   - ESP32 的通用定时器群（Timer Group）缺乏这种高度紧密集成的片上硬件触发总线，通常必须通过“I2S 并口模式”或“GDMA 连续捕获”等特殊技巧来间接实现，底层寄存器配置极其晦涩复杂。

#### 3) 终极破解折中方案：ESP32 + 独立外挂高速 SPI ADC
如果团队强烈倾向于在协处理器上**统一采用 ESP32 技术栈**，最优雅的工业化落地架构是：**“彻底弃用 ESP32 内部劣质 ADC，外挂一颗低成本工业高速 SPI ADC”**。

```
  ┌─────────────────────── 推荐改型架构 (兼得技术栈与高精度) ───────────────────────┐
  │                                                                                 │
  │  [ TCD1304 线阵 CCD ] ───(模拟OS)───> [ 运放 OPA350 ]                           │
  │           ▲                                    │                                │
  │           │                                    ▼                                │
  │           │                           ┌──────────────────┐                      │
  │           │ (MCPWM 生成时钟)          │ 独立高速 ADC 芯片 │ (如 AD7476 / ADS7886) │
  │           │                           │ (12-bit, 1~2Msps)│ (单价约 ¥3.5)        │
  │           │                           └────────┬─────────┘                      │
  │           │                                    │ 高速 SPI + DMA                 │
  │  ┌────────┴────────────────────────────────────▼────────┐                       │
  │  │                  协处理器 MCU: ESP32-S3 / ESP32      │                       │
  │  │  ✔ 统一 PlatformIO 工具链                            │                       │
  │  │  ✔ 双核 240MHz 高速亚像素插值算法                    │                       │
  │  │  ✔ 通过 UART 向上位机交付直径浮点值                  │                       │
  │  └──────────────────────────────────────────────────────┘                       │
  └─────────────────────────────────────────────────────────────────────────────────┘
```
- **器件配置**：选用 **AD7476** 或 **ADS7886**（12-bit，1~2.5 Msps，6-pin SOT-23 极小封装，采购成本仅 ¥3~4）；
- **数据通路**：ESP32 通过硬件 SPI 总线（40MHz 甚至 80MHz）配合片上 SPI-DMA 极速将 3648 像元数据拉入内存；
- **收益**：既获得了 STM32 级别的线性度和信噪比，又保留了 ESP32 统一开发环境、充沛算力和未来可选 Web 波形调试的全部优势。

## 3. 左侧：传感器物理接口与调理电路设计

以核心传感器 **Toshiba TCD1304AP/DG** 为例：

### 3.1 驱动时序要求与硬件定时器映射
TCD1304 工作需要 3 组关键数字控制信号：
1. **$\text{CLK}$ (主时钟)**：典型频率 $2.0\text{ MHz}$（方波，50% 占空比）；
2. **$\text{ICG}$ (像元转移门脉冲)**：负脉冲，低电平持续时间 $> 5\text{ }\mu\text{s}$，周期决定行读出周期（通常 $2\text{ ms} \sim 5\text{ ms}$）；
3. **$\text{SH}$ (电子快门门脉冲)**：正脉冲，高电平持续时间 $> 1\text{ }\mu\text{s}$。$\text{ICG}$ 变低后紧随的第一个 $\text{SH}$ 脉冲将感光电荷转移至移位寄存器，两个脉冲之间的间隔决定物理**曝光时间**。

#### STM32 硬件级联无 CPU 开销配置：
- **主定时器 TIM1**：配置为 PWM 模式，直接在输出引脚上持续输出 $2.0\text{ MHz}$ 硬件方波作为 $\text{CLK}$；
- **从定时器 TIM2**：由 TIM1 作为时钟触发源进行分频计数，输出周期性的 $\text{ICG}$ 与 $\text{SH}$ 脉冲；
- **全程零 CPU 中断介入**，彻底杜绝时钟抖动。

```
                  TCD1304 硬件驱动关键时序波形:
                  
  CLK  (2MHz)   ┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐
                └┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘└┘
  ICG (转移门)  ──────┐                       ┌──────────────────────
                      └────── 5 μs ───────────┘
  SH  (快门门)  ─────────────┐   ┌───────────────────────────────────
                             └───┘ 2 μs
  OS  (模拟输出) ────────────[ 伪像元 ]───[ 3648 点真实有效像素波形 ]────
```

### 3.2 模拟调理电路 (OPA350 运放架构)
- **信号特性**：TCD1304 的模拟输出脚 $\text{OS}$ 呈负极性调制（光照越强输出电压越低），且叠加了约 $1.8\text{ V} \sim 2.5\text{ V}$ 的直流偏置电平，幅值动态范围约为 $500\text{ mV}$；
- **调理方案**：
  采用低噪声、轨到轨高速精密运放 **OPA350**（增益带宽积 38MHz）：
  1. 采用交流耦合或差分运放减除直流偏置；
  2. 实施 $3\times$ 放大，将 $500\text{ mV}$ 摆幅线性拉伸至 $0\text{ V} \sim 2.5\text{ V}$，完美填满 STM32 ADC 的有效量程；
  3. 配置一阶低通滤波器（截止频率设为 $4\text{ MHz}$），滤除时钟馈通毛刺（Clock Feedthrough Noise）。

## 4. 固件算法链路：从像素波形到外径毫米值

### 4.1 DMA 乒乓双缓冲采集机制
- 配置 ADC1 规则通道，以 $2.0\text{ Msps}$ 采样率连续转换，由 DMA2 Stream0 自动搬运至内部内存；
- 设置两块独立缓存数组：`uint16_t buffer_A[3648]` 和 `uint16_t buffer_B[3648]`；
- 当 `buffer_A` 被 DMA 填满时，DMA 自动切换至 `buffer_B`，同时向 CPU 发送半传输完成中断，CPU 在后台并发处理 `buffer_A`，**采集与运算无缝流水线化**。

### 4.2 片上亚像素边缘提取算法 (Sub-Pixel Algorithm)

```
       像元灰度值 V(n)
        ▲
   V_high ────┐                                           ┌──── (高亮透光区)
              │ ＼                                     ／ │
              │   ＼ 阈值穿越点                     ／   │
   V_th   ────┼─────★ (亚像素插值)       (亚像素插值)★─────┼──── (50% 动态阈值)
              │       ＼                         ／       │
   V_low  ────┴─────────＼─────────────────────／─────────┴──── (芦笋遮挡暗区)
              0         n_bottom              n_top      3648  (像元序号)
                         │◄──── 遮挡阴影宽度 ───►│
```

1. **动态自适应阈值计算**：
   在单帧数据中提取阴影区最低值 $V_{\text{low}}$ 与背景光最高值 $V_{\text{high}}$：
   $$V_{\text{th}} = V_{\text{low}} + 0.5 \times (V_{\text{high}} - V_{\text{low}})$$
2. **亚像素线性内插**：
   定位穿越阈值的相邻两个整数像元 $n_k$ 与 $n_{k+1}$（满足 $V(n_k) \le V_{\text{th}} < V(n_{k+1})$）：
   $$n_{\text{edge}} = n_k + \frac{V_{\text{th}} - V(n_k)}{V(n_{k+1}) - V(n_k)}$$
3. **直径物理量换算**：
   $$\text{Diameter (mm)} = |n_{\text{edge\_top}} - n_{\text{edge\_bottom}}| \times K_{\text{scale}}$$
   （其中 $K_{\text{scale}} \approx 0.0123\text{ mm/pixel}$，由标定确定）。

## 5. 右侧：与 head 主控 (ESP32) 的通信与交互协议

协处理器与主控之间仅保留 4 根导线（`TXD`, `RXD`, `TRIG`, `GND`），支持两种工作模式：

### 5.1 工作模式设计

#### 模式 1：硬件飞拍触发应答模式 (Trigger-Response，工业推荐)
- **触发**：芦笋到达指定截面时，ESP32 将 `TRIG` 引脚拉低 $10\text{ }\mu\text{s}$ 脉冲（或发送指令 `{"cmd":"trig"}\n`）；
- **响应**：协处理器捕获到硬件中断，立即启动单次曝光采集与边缘解算；
- **交付**：在 **$2.5\text{ ms}$** 内，通过 UART 向上位机发送单行 JSON 报文，测量完成。

#### 模式 2：自动连续流广播模式 (Continuous Stream)
- 协处理器以固定频率（如 50Hz 或 100Hz）持续测算并在串口广播直径，ESP32 在物料经过时直接拾取最新一帧或多帧中值滤波。

### 5.2 串口通信协议规格
- **物理层**：UART，波特率 **$115200\text{ bps}$**（或 $460800\text{ bps}$），8 位数据，1 位停止位，无奇偶校验；
- **报文格式**：标准单行 JSON 文本，以 `\n` 结尾，便于调试与解析。

#### 正常测量应答报文：
```json
{
  "diam_mm": 16.48,
  "top_px": 2840.35,
  "bot_px": 1500.12,
  "exp_us": 500,
  "status": "OK"
}
```

#### 异常状态应答报文：
| 状态码 (`status`) | 触发条件 | 含义与主控处理建议 |
| :--- | :--- | :--- |
| `"OK"` | 正常识别到上下双边缘 | 测量有效，直接作为有效直径入库 |
| `"NO_OBJECT"` | 全视场无阴影遮挡 ($V(n)$ 全高) | 芦笋未到位或已离开，报空载 |
| `"OVER_RANGE"` | 芦笋尺寸超过视场或位置严重偏出 | 直径过粗或摆放严重偏歪，上报故障 |
| `"OVER_EXPOSURE"`| 背光过强导致像元饱和溢出 | 需调小曝光时间或降低背光源电流 |
| `"LOW_CONTRAST"` | 阴影落差不足 ($V_{\text{high}} - V_{\text{low}} < \text{Threshold}$)| 背光窗口被泥污严重覆盖，触发清洁告警 |

## 6. 电气隔离与抗干扰硬件实施

```
     ┌──────────────────────┐             ┌─────────────────────┐
     │  协处理器模块 (STM32) │             │  head 主控 (ESP32)  │
     │                      │   高速光耦  │                     │
     │      UART_TX ────────┼───[ 6N137 ]─┼───> DATA_UART_RX    │
     │      UART_RX <───────┼───[ 6N137 ]─┼───── DATA_UART_TX   │
     │      TRIG_IN <───────┼───[ EL357 ]─┼───── GPIO_TRIG_OUT  │
     │                      │             │                     │
     │      隔离 GND_CCD    │             │     系统 GND_MAIN   │
     └──────────────────────┘             └─────────────────────┘
```

1. **光电隔离设计**：
   在流水线大功率输送步进电机频繁启停的环境下，地线易串入尖峰干扰脉冲。协处理器串口与触发引脚建议串联高速光耦（如 6N137 或磁耦芯片 CA-IS3082），将微弱模拟光学测量地与动力驱动地物理隔离；
2. **模拟/数字独立分区供电**：
   CCD 供电使用独立的低压差、低纹波 LDO（如 TPS73233，纹波 $< 30\text{ }\mu\text{V}$），避免电机共用 12V 降压母线纹波调制在视频信号上。

## 7. 结论与工程价值

通过构建这套独立的前置协处理器小系统：
1. **主控彻底解放**：`head` ESP32 仅需一条非阻塞 `Serial.read()` 指令即可获得高精度浮点直径，系统架构极其清爽，完全符合 YAGNI 与极简解耦准则；
2. **微秒级性能释放**：传感器硬件驱动与纳秒级时序交由专用 ARM Cortex-M4 硬件定时器处理，彻底消除了操作系统级的时钟抖动；
3. **即插即用模块化**：该子系统既可用于本项目的芦笋测径，未来也能独立作为通用的工业高精度微米级激光/阴影测径仪模组对外复用。
