## 1. 方案概述与系统哲学 (Philosophy)

### 1.1 从“专用硬件时序”到“通用高算力纯软件”
在测量方案的演进中：
- **方案一（机电式）**：依赖步进电机横向滑台机械移动来扫描单点直径；
- **方案二（一维光学式）**：依赖线阵 CCD（或三线阵彩色 CCD）纳秒级严苛时序驱动与高速 ADC 采集；
- **方案三（二维面阵纯视觉软件式）**：彻底卸下微控制器对脉冲时钟与底层硬件波形的束缚，转向**现代工业边缘计算（Edge Computing）与纯机器视觉软件分析**。

### 1.2 系统组成模型
方案三采用**“全局快门工业面阵相机 + 嵌入式高算力平台（如树莓派 4B/5 或 RK3588）”**构成独立的智能视觉测量站：
1. **光学传感**：全局快门（Global Shutter）彩色工业相机（如 Sony IMX296 传感器，像素 $1440 \times 1080$ 或 $1920 \times 1200$）；
2. **算力核心**：树莓派 5 / 4B（四核 ARM Cortex-A76/A72 @ 1.8~2.4GHz，内存 2GB~4GB），运行 Linux + OpenCV；
3. **工作模式**：芦笋随传送带高速前行通过视场，光电触发单次曝光（$\le 200\text{ }\mu\text{s}$）抓取一张 2D 高清彩色照片，在软件中通过图像算法**一次性同时解算出直径分布 $D(x)$、绿白分界点、有效绿长 $L_{\text{green}}$ 与总长 $L_{\text{total}}$**；
4. **交付方式**：树莓派通过板载 UART 串口直接向 `head` ESP32 发送单行测量结果 JSON 数据包。

## 2. 关键硬件设计考量

### 2.1 为什么必须是“全局快门 (Global Shutter)”？
普通消费级相机或廉价工业相机采用**卷帘快门（Rolling Shutter）**：
- 传感器逐行曝光，当芦笋以 $200\text{ mm/s}$ 速度横向飞过时，图像顶部与底部曝光存在数毫秒时差，产生严重的**“果冻效应（Jello Effect）”与斜向剪切形变**，导致长度和直径产生高达数毫米的致命测量失真；
- **全局快门（Global Shutter）**：感光阵列中所有像素在同一微秒瞬间同时曝光、同时锁存电荷，**彻底杜绝任何运动畸变**。在 $100\sim 200\text{ }\mu\text{s}$ 短曝光下，高速运动物料如同完全静止。

### 2.2 视场 (FOV) 与光学空间分辨率匹配
- **视场范围设计**：芦笋最大全长约 $250\text{ mm}$，最大直径 $30\text{ mm}$。考虑进料位置摆放公差，物方视场设计为：
  $$W_{\text{FOV\_X}} = 300\text{ mm} \quad (\text{长度方向}), \qquad H_{\text{FOV\_Y}} = 80\text{ mm} \quad (\text{宽度方向})$$
- **空间分辨率推导**：
  若选用 200 万像素全局快门相机（如分辨率 $1920 \times 1200$）：
  $$R_{\text{pixel}} = \frac{300\text{ mm}}{1920\text{ pixel}} \approx \mathbf{0.156\text{ mm/pixel}}$$
  - 配合 OpenCV 亚像素边缘拟合（`cv::findContours` + 矩分析），直径测量精度可达 **$\pm 0.05\text{ mm} \sim \pm 0.1\text{ mm}$**，长度精度达 $\pm 0.2\text{ mm}$，完全契合农产品分选国标要求。

## 3. 纯软件算法处理链路 (Software Pipeline)

在树莓派中，算法处理完全基于标准软件库（C++ 或 Python OpenCV），逻辑极其透明、易于直观调试：

```python
# 核心算法处理示意 (伪代码)
def process_asparagus_frame(color_img):
    # 1. 灰度化与 Otsu 自适应二值化提取完整轮廓
    gray = cv2.cvtColor(color_img, cv2.COLOR_BGR2GRAY)
    _, mask = cv2.threshold(gray, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)
    
    # 2. 提取最大连通域轮廓
    contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_NONE)
    stem_cnt = max(contours, key=cv2.contourArea)
    
    # 3. 拟合芦笋主轴中心线并求头尾端点
    [vx, vy, x0, y0] = cv2.fitLine(stem_cnt, cv2.DIST_L2, 0, 0.01, 0.01)
    
    # 4. 沿主轴垂直法向每隔 1mm 计算切片宽度，提取直径 Profile D(x)
    diam_profile = calculate_slice_widths(stem_cnt, x0, y0, vx, vy)
    base_diameter = diam_profile[spec_point_offset] # 距头部基准处的直径
    
    # 5. HSV 色彩空间分析有效绿长 (截取轮廓内部色彩)
    hsv = cv2.cvtColor(color_img, cv2.COLOR_BGR2HSV)
    green_mask = cv2.inRange(hsv, LOWER_GREEN, UPPER_GREEN)
    green_length_mm = calculate_green_axial_extent(green_mask, x0, y0, vx, vy)
    
    # 6. 打包单行 JSON 经 UART 发送
    return {"diam_mm": round(base_diameter, 2), "green_len_mm": round(green_length_mm, 1), "status": "OK"}
```

- **处理耗时**：树莓派 5 在 1080P 分辨率下运行上述 C++ 算法单帧耗时仅约 **$15\text{ ms} \sim 25\text{ ms}$**，完全满足流水线每秒 2~3 根（节拍 300~500ms）的高吞吐要求。

## 4. 方案三的优劣势剖析

### 4.1 核心优势 (Pros)
1. **纯软件开发，迭代效率极高**：
   - 彻底免除硬件定时器、ADC/DMA 寄存器、时钟抖动的底层调试烦恼；
   - 算法可随时打断点、保存现场图片、离线批量回放测试，开发与演进门槛最低；
2. **全形态一次性提取（数据维度最丰富）**：
   - 一张照片即可得到**整笋总长、有效绿长、任意截面直径、弯曲度、笋尖松散度、表皮损伤面积**，为未来进阶引入 AI 深度学习外观缺陷检测留足了扩展空间；
3. **机械结构极度精简**：
   - 流水线上只有一个相机镜头垂直/侧向俯瞰，无任何运动摩擦滑台，物料全程直线匀速通过。

### 4.2 核心挑战与短板 (Cons)
1. **视场跨度大，光学暗箱与大面积光源成本高**：
   - 要完整覆盖 $300\text{ mm}$ 长的芦笋，必须配备长条大面积背光板（如 $350\text{mm} \times 120\text{mm}$），且需要较大的工作距离（镜头距离传送带通常需 $300\text{mm} \sim 500\text{mm}$），整机高度尺寸增大；
2. **BOM 硬件成本最高**：
   - 全局快门工业相机（¥260~380）+ 树莓派 5/4B 主板（¥320~450）+ 大面积工业光源（¥180）$\approx$ **¥ 800 ~ 1000 RMB**，相比前两套微控制器方案（¥150~300）成本明显更高；
3. **Linux 嵌入式系统的维护复杂度**：
   - 包含 Linux 操作系统与 MicroSD 卡存储，相比裸机单片机存在意外断电文件系统损坏风险，工业化量产需配置只读文件系统（OverlayFS）。

## 5. 总结与应用定位

方案三是现代工业自动化中最具前瞻性和通用性的**“交钥匙视觉方案”**：
- 它适合追求极高功能集成度、未来规划加入 AI 缺陷检测、且对整机 BOM 成本不敏感的高端机型；
- 与方案一（低成本机电验证）和方案二（极速一维光电硬件）共同构成了 thin_wall 项目三大可选的技术支柱。
