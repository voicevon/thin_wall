# 用户交互与提问准则：批量集中准备，严禁乒乓式碎打 (Batch Questions Policy)

本规则约束所有子项目与会话中的用户提问与需求澄清行为：

1. **严禁单题乒乓式拉扯与等待**：
   - **绝对禁止**问用户一个问题，等待用户回答后，再思考一段时间，然后又抛出下一个问题；
   - 严禁碎片化、多轮次打断用户，严禁无谓占用和浪费用户的在线等待时间。

2. **集中梳理、打包一次性提出**：
   - 遇到需求不明确、需要用户决策或涉及多个参数时，必须提前将所有相关问题一次性准备充分；
   - 优先使用交互组件（如 `ask_question` 的多题列表）集中抛出所有问题，让用户一次性勾选确认或输入，将多轮往返压缩为单次高效交互；
   - 每个问题必须提供具象、明确的预设选项，降低用户打字与思考负担。
