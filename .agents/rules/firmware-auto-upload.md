# 固件编译后自动下载规则 (Firmware Auto-Upload Policy)

本规则约束所有 ESP32 / PlatformIO 嵌入式固件子项目（包括 `head`、`water_sensor_hx711`、`water_relay` 等）：

1. **当前模式状态**：
   - **自动烧录：已开启 (Auto-Upload: ENABLED)**。
   - 用户已明确指示：“从现在开始就进入下载，且希望能够跨会话持久化”。

2. **自动化标准作业流程 (SOP)**：
   - 每当助手完成固件代码编写、Bug 修复、参数调整或重构后：
     1. **步骤一 (编译构建)**：自动执行 `pio run -d <子工程目录>` 验证语法与链接；
     2. **步骤二 (自动烧录)**：编译成功 (`[SUCCESS]`) 后，**严禁停下等待，必须立即自动执行硬件烧录下载命令**：
        ```powershell
        pio run -d <子工程目录> -t upload
        ```
     3. **步骤三 (汇报结果)**：向用户清晰汇报编译 Flash/RAM 占用率、串口下载进度与运行状态。

3. **异常处理原则**：
   - 若烧录过程中提示串口被占用（如 VSCode/PlatformIO 串口监视器开启导致串口被锁）：提示用户关闭串口监视器后一键重试；
   - 若未检测到目标 COM 端口：向用户报告未识别到开发板，并提示检查 USB 数据线或电源。

4. **状态切换机制**：
   - 本规则保存在工作区规则库中，所有新开会话均会自动作为全局规则加载生效；
   - 若用户在任意会话中输入“关闭自动下载”、“停止下载”、“仅编译不下载”，助手将修改本规则状态为 `DISABLED` 并停止自动烧录。
