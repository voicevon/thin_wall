# thin_wall 芦笋智能检测与分级分选系统

本项目是一套面向农业与食品加工场景的**分布式模块化 ESP32 芦笋智能流水线检测与分选系统**。
系统采用类似**“火车头 + 级联车厢 (Locomotive & Cascaded Carriages)”**的前后端解耦架构：
- **`head`（火车头）**：领头前端，负责芦笋的入料识别、测长测径、定位与数据首发；
- **`body`（级联车厢 / Dealer 分牌器）**：由**多个完全相同、硬件标准化**的 ESP32 分选单元串联而成（`body_1` ➔ `body_2` ➔ `body_3` ➔ ... ➔ `body_N`），像火车车厢一样按需无缝横向拼接，实现多级分流与智能分选。

## 2. 子项目职责划分

### 2.1 `head` —— 识别、测长、测径与定位入料系统 (火车头)
- **主控芯片**：ESP32
- **角色定位**：全线的领头调度者与测量基准。
- **核心职责**：
  1. **物料感知与入料推进**：检测芦笋入料，驱动单向输送电机平稳推进定位；
  2. **有效绿长测量**：双 TCS34725 颜色传感器（前哨预警 + 精测量基准）协同工作，动态平滑降速并高精捕捉绿白分界临界点；
  3. **横向直径测量**：Y 轴微光斑激光传感器横向扫描芦笋，精确计算外径尺寸；
  4. **补光控制**：双路 LED 补光灯上电后常亮，保证待机时能可靠识别放料；
  5. **测量数据首发**：将唯一编号、绿长、外径打包向下游级联总线首发广播（**不做定级**，定级由 `body` 完成）。
- **详细文档与引脚配置**：参见 [head/README.md](head/README.md)。

---

### 2.2 `body` —— 模块化分选与分流机构 (级联车厢 / Dealer)
- **主控芯片**：每个分选车厢各搭载 1 片 ESP32。
- **角色定位**：标准化的**分牌器（Dealer）**执行单元，硬件与固件统一设计，支持多节点串联。
- **核心职责**：
  1. **标准化单车厢固件**：一套通用固件，拨码开关设节点号，等级规则通过串口命令写入 NVS（可现场修改）；
  2. **本地定级与分流 (Dealer 逻辑)**：
     - 接收上游转发来的测量值（绿长、直径），按本节规则判定是否归本节；
     - **目标命中**：芦笋到达后由分流执行器拨入本节出料仓，数据包不再往下游转发；
     - **放行传递**：不归本节的芦笋放行，数据包原样转发给下一节；
  3. **到达同步**：每节自带一段传送带和入口光电，用先进先出队列对应实物，光电触发后按电机步数定位分流时机；
  4. **扩展灵活性**：需要增加分类级别或出料口时，仅需在线路尾部“挂载新车厢”，无需重构既有系统。
- **详细文档与引脚配置**：参见 [body/README.md](body/README.md)。

## 3. 协同机制与通信总线规范

全系统由 1 个 `head` 节点与 $N$ 个 `body` 节点构成分布式局域控制网络：

### 3.1 物理通信架构与背压握手协议
- **全双工双向 UART 菊花链 (Daisy-Chain)**：
  - **前向传输 (TX ➔ RX)**：`head` ➔ `body_1` ➔ `body_2` ➔ ... 逐级传递物料测量数据；
  - **反向状态通告 (TX ➔ RX)**：后机向前机定时（默认 50ms）广播自身运行状态：
    ```json
    {"node": 1, "state": "IDLE"}
    ```
    - 状态枚举：`IDLE` (空闲)、`RECEIVING` (接收中)、`SENDING` (发送中/分选执行中)；
- **严格背压互锁原则**：
  - **只有后机处于 `IDLE` 空闲状态，前机才获准发送数据和启动电机推送芦笋**；
  - **若后机处于 `RECEIVING`、`SENDING` 或通信超时未响应，前机必须原地停机等待，严禁发送芦笋和数据**；
- 物理层增强：相邻两节距离较远时，每段加一对 RS485 收发器做抗干扰传输。

### 3.2 典型数据报文示例 (JSON)
`head` 完成测量后发出的流水线数据包：
```json
{
  "item_id": 1024,
  "green_length_mm": 185.4,
  "diameter_mm": 12.8,
  "status": "OK"
}
```

### 3.3 时序协作流程 (锁步受控交接)
1. **火车头测定**：`head` 完成芦笋绿长与直径扫描，芦笋尾部离开检测区；
2. **反向状态确认**：`head` 监听 `body_1` 状态心跳：
   - 若 `body_1` 为 `RECEIVING` 或 `SENDING`，`head` 输送电机停机原地等待；
   - 一旦 `body_1` 上报 `IDLE`，`head` 发送测量报文并启动电机将芦笋推入 `body_1`；
3. **车厢接力 (Dealer 响应)**：
   - `body_k` 接收物料时切换为 `RECEIVING`（阻止上游继续推料）；
   - 入口光电感应物料到位，判定定级规则：
     - **归本节**：状态转为 `SENDING`，步进电机带动物料到分流位，执行器拨料入仓；动作完成后切回 `IDLE`；
     - **归下游**：状态转为 `SENDING`，监听下游 `body_k+1` 状态。**原地等待下游变 `IDLE`**，随后向下一节转发报文并开动电机交接物料；交接完成切回 `IDLE`；
4. **末端兜底**：最后一节设为 `catch_all`，收集所有未命中或测量异常的芦笋。

## 5. 软件与技术栈

- **构建系统**：PlatformIO
- **开发框架**：Arduino Core for ESP32
- **架构哲学**：
  - **高内聚、低耦合**：`head` 专心做好高精度测量，`body` 专注于模块化可靠分选；
  - **弹性可扩展**：硬件接口与软件协议标准化，车厢单元可复制化批量部署。
